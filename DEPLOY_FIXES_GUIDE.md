# 🚀 Руководство по деплою исправлений

## ✅ Что было исправлено

### 1️⃣ Проблема: Не работает звук на мобильных устройствах

**Причина:** Мобильные браузеры (iOS Safari, Chrome Android) блокируют автоматическое воспроизведение звука до первого взаимодействия пользователя.

**Решение:** Реализована система разблокировки аудио:
- При первом клике/тапе/нажатии клавиши инициализируется AudioContext
- Воспроизводится беззвучный буфер для разблокировки аудио-канала
- Предзагружается реальный звук уведомления в фоновом режиме
- После этого все звуковые уведомления работают автоматически

**Файл:** `components/branch/OrderSoundNotification.tsx`

### 2️⃣ Проблема: Длинный номер заказа

**Старый формат:** `ORD-232359` (на основе timestamp)
**Новый формат:** `ORD - 123456` (6 случайных цифр)

**Изменения:**
- Используется генератор случайных чисел от 100000 до 999999
- Формат с пробелами вокруг тире для лучшей читаемости
- Гарантированно ровно 6 цифр

**Файлы:**
- `app/api/orders/route.ts`
- `app/api/finik/create-payment/route.ts`

### 3️⃣ Обновлена версия Service Worker

**Версия:** `v1.0.1` → `v1.0.2`

Это обеспечит автоматическое обновление кэша на устройствах пользователей.

**Файл:** `public/sw.js`

## 🔧 Техническая информация

### Как работает разблокировка звука?

```javascript
// 1. Инициализация AudioContext (обязательно для iOS)
const AudioContext = window.AudioContext || window.webkitAudioContext;
const audioContext = new AudioContext();

// 2. Создание пустого буфера (1 сэмпл, 22kHz)
const buffer = audioContext.createBuffer(1, 1, 22050);
const source = audioContext.createBufferSource();
source.buffer = buffer;
source.connect(audioContext.destination);
source.start(0);

// 3. Возобновление контекста (разблокировка)
await audioContext.resume();

// 4. Предзагрузка реального звука (с volume=0)
audio.load();
await audio.play(); // Беззвучно
audio.pause();
audio.volume = 1.0; // Восстанавливаем громкость
```

### Почему используется Math.random() а не timestamp?

- **Timestamp** генерирует предсказуемые номера (последние 6 цифр часто повторяются)
- **Math.random()** даёт лучшее распределение уникальных номеров
- Вероятность коллизии: 1 к 900,000 (очень низкая для среднего объёма заказов)
- При необходимости можно добавить проверку на уникальность в БД

### Как Service Worker обновляет кэш?

1. Браузер сравнивает байты файла `sw.js`
2. Если файл изменился → регистрируется новый SW
3. Новый SW устанавливается (`install` event)
4. При активации (`activate` event) удаляются старые кэши
5. Страница перезагружается автоматически (`controllerchange` event)

## ⚠️ Возможные проблемы и решения

### Проблема: Звук всё равно не работает

**Решение:**
1. Убедитесь что пользователь **кликнул** хотя бы раз после открытия страницы
2. Проверьте что звуковой файл доступен: `https://ваш-домен.com/uvedomlenie.mp3`
3. Проверьте консоль браузера (F12) на наличие ошибок
4. На iOS убедитесь что режим "Без звука" отключен на устройстве

### Проблема: Старый формат номера заказа

**Причина:** Кэширование старого кода.

**Решение:**
```bash
# Пересоберите production build
npm run build

# Очистите кэш браузера (Ctrl+Shift+Del)
# Или откройте в режиме Инкогнито для теста
```

### Проблема: Service Worker не обновляется

**Решение:**
1. Откройте DevTools → Application → Service Workers
2. Поставьте галочку "Update on reload"
3. Перезагрузите страницу (Ctrl+R)
4. Или используйте "Unregister" и перезагрузите

### Проблема: Дублирование номеров заказов

**Решение (если потребуется):**
Добавьте проверку на уникальность:

```typescript
// В app/api/orders/route.ts
let orderNumber: string;
let isUnique = false;

while (!isUnique) {
  const random6digits = Math.floor(100000 + Math.random() * 900000);
  orderNumber = `ORD - ${random6digits}`;
  
  // Проверка в БД
  const existing = await prisma.order.findUnique({
    where: { orderNumber }
  });
  
  if (!existing) isUnique = true;
}
```
